# myzgoal 执行计划

> 为 PI Agent 实现 Claude Code 的 `/goal` 命令。

## 一、调研结论

### 1. PI Agent 扩展机制(来源:pi 官方 docs/extensions.md 与 examples/extensions/)

- 扩展是导出默认工厂函数的 TypeScript 模块,经 jiti 直接运行,无需编译。
- 放置位置:`~/.pi/agent/extensions/`(全局)或 `.pi/extensions/`(项目级),支持 `/reload` 热重载;也可作为 pi 包分发(`package.json` 中 `"pi": {"extensions": [...]}`)。
- 本次用到的关键 API:

  | API | 用途 |
  | --- | --- |
  | `pi.registerCommand("goal", ...)` | 注册 `/goal` 命令 |
  | `pi.sendUserMessage(text, {deliverAs})` | 注入用户消息并**触发新回合**(实现自动续跑) |
  | `ctx.modelRegistry.complete(model, messages, opts)` | 嵌套 LLM 调用(实现评估器) |
  | `ctx.sessionManager.getBranch()` | 读取会话上下文供评估器判断 |
  | `pi.appendEntry(customType, data)` | 会话内持久化目标状态(resume 可恢复),不进入 LLM 上下文 |
  | `pi.registerEntryRenderer()` | 自定义条目在转录中的渲染 |
  | `ctx.ui.setWidget()/notify()` | `◎ /goal active` 状态指示与提示 |
  | `pi.on("agent_settled", ...)` | 每回合集束(无自动重试/压缩/后续消息)后触发评估 |
  | `pi.on("session_start", ...)` | resume 时恢复活跃目标 |

### 2. Claude Code `/goal` 命令语义(来源:code.claude.com/docs/en/goal)

- `/goal <condition>`(≤4000 字符):设置完成条件,**立即以该条件为指令开启一个回合**。
- 每回合结束后,由一个**独立的小快模型**(默认 Haiku)只读对话内容评估:
  - `not_yet met` → 清除目标权仍在主模型手里;带"理由"作为下一回合指导自动续跑;
  - `met` → 清除目标并在转录中记录达成条目;
  - `impossible` → 清除目标并记录失败条目及原因。
- 评估器不调用工具、不读文件,只能依据主模型在对话中呈现的内容判定 → 条件应写成"可证明的端状态"(如 `npm test` 退出 0)。
- `/goal` 无参:显示条件、运行时长、已评估回合数、token 花费、最近一次理由。
- `/goal clear`(别名 stop/off/reset/none/cancel)提前移除;`/clear` 新会话亦移除。
- 保护区:
  - 连续多回合无工具调用(无进展)→ 停止循环、警告、**保留目标**,下次 prompt 后恢复评估;
  - 不可恢复错误(认证、余额、无法压缩的上下文溢出、模型不可用)→ 清除目标并警告;瞬时错误(限流等)保留目标。
  - 后台任务运行时推迟评估,30 分钟后发起 check-in(指数退避,v1 简化)。
- resume 恢复仍活跃的目标:保留条件,重置回合数/计时/token 基线。
- 非交互模式 `-p "/goal ..."` 单次调用跑完整个循环。

## 二、架构设计

```text
/goal <condition> ──► 存目标(appendEntry) ──► sendUserMessage(条件指令) 开启首回合
                                                            │
每回合结束(agent_settled) ──► 评估器(小模型, 只读会话上下文) ─┤
        │  verdict                                            │
        ├─ not_yet ──► sendUserMessage(理由作为指导) 续跑 ────┘
        ├─ met ──────► 清目标 + appendEntry(goal-achieved) + 通知
        └─ impossible ► 清目标 + appendEntry(goal-failed) + 通知

守卫:连续 N 回合无工具调用 → 停循环保目标;评估/续跑自身出错 → 停循环保目标。
状态恢复:session_start 扫描 appendEntry 条目重建内存态(resume 兼容)。
```

模块划分:

```text
myzgoal/
├── package.json          # pi 包清单(pi.extensions) + 依赖
├── LICENSE               # MIT
├── README.md
├── src/
│   ├── index.ts          # 入口:命令注册、事件接线
│   ├── state.ts          # 目标状态(内存 + appendEntry 持久化/恢复)
│   ├── evaluator.ts      # 小模型评估器(verdict 解析)
│   └── render.ts         # 条目渲染器 + widget 文本
```

## 四、只给方案、不实现的部分

### 1. 集成到本机 pi 环境

两种方式(推荐 A):

#### A. 作为 pi 包安装(可复现、可升级)

```bash
pi install git:github.com/applearound/myzgoal
```

pi 会克隆仓库、执行生产依赖安装、按 `package.json` 的 `pi.extensions` 字段加载。

#### B. 本地开发软链(调试用)

```bash
ln -s ~/Dev/mine/myzgoal ~/.pi/agent/extensions/myzgoal
```

目录内含 `index.ts`(或由 package.json 指向 `src/index.ts`),改动后 `/reload` 热重载。

### 2. 发布到 npm

1. `package.json` 填写 `name`(`myzgoal` 或 `@applearound/myzgoal`)、`version`、`files`(只含 `src`、`README.md`)、`pi.extensions` 字段;
2. `npm publish`(pi 的包安装机制用生产安装,运行时依赖须放 `dependencies`,如 `@earendil-works/pi-ai`);
3. 打 git tag(`v0.1.0`)并与 npm 版本对齐;
4. 之后即可 `pi install npm:myzgoal` 或写入 `settings.json` 的 `packages` 数组。

## 五、AI 时代的 Git Workflow

原则:AI 产出量大、迭代快,必须**小步提交、可回滚、机器可审计**。

1. **Trunk-based**:`main` 永远可用;功能在短命分支 `feat/<slug>` 开发。
2. **Conventional Commits**:`feat:`/`fix:`/`docs:`/`refactor:`/`chore:`,供 changelog 自动生成与语义化版本推断。
3. **每完成一个原子单元即提交**(AI 一个任务一个 commit),commit message 说明"为什么";PR(或本地 merge --squash)合入 main。
4. **Tag 发布**:`v0.1.0` 起 semver,发布即 tag,tag 与 npm 版本一一对应。
5. **文档即代码**:调研、决策、计划全部入库(`docs/`),AI 上下文可随时重建。
6. GitHub 侧:启用 branch protection(main 禁止 force push)、PR 要求通过本地验证后再合。

## 六、配置界面与持久化方案(v0.2.0)

### 持久化位置(与 pi settings.json 同构)

| 层级 | 文件 | 生效条件 |
| --- | --- | --- |
| 项目级 | `<项目>/.pi/myzgoal.json` | 仅 trusted 项目生效,适合团队共享 |
| 全局 | `~/.pi/agent/myzgoal.json` | 个人默认 |

每个配置项的优先级:**环境变量 > 项目文件 > 全局文件 > 内置默认**。
写入时保留文件中的未知键(无损合并);`"evaluatorModel": ""` 表示删除该键(回到自动选择)。

### 配置界面(/goal-config)

基于 pi-tui 的 `SettingsList` 实现(通行做法四层中的"完整层"):

- 评估模型:子面板用 `SelectList` 展示已认证模型(按输入单价升序)+ `(auto)` 选项
- 评估次数上限 / 无进展阈值:`values` 循环切换
- 写入位置:project/global 切换(project 未受信时锁定为 global,仅影响本次保存,不持久化)

关键机制:`SettingsList` 的 values 循环与子面板关闭都会自动更新显示并回调 `onChange(id, newValue)`,
因此持久化逻辑集中在单一 onChange 回调:写文件 → 重算 effective config → `updateValue` 刷新来源标签。
每行显示"生效值 · 来源(env/项目/全局/默认)"。
